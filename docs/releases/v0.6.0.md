# CC Port v0.6.0 Public Beta

[English release notes](https://github.com/Ling-ye/cc-port/blob/main/docs/releases/v0.6.0.en.md)

CC Port `v0.6.0` 是 `v0.5.4` 之后的一次较大功能更新：安装包首次包含独立的
`cc-port.exe` CLI/MCP agent，资源仓库切换到工具中立的 Registry v1，并增加
Windows/WSL 独立 profile、Claude Code 用户指令与 auto memory，以及按 Claude
原生语义区分的 Skill、skills-directory Plugin 和 Marketplace Plugin 工作流。

## 下载

- `cc-port_0.6.0_windows_x64_setup.exe`
- `SHA256SUMS.txt`

下载后请先核对 SHA-256，再运行安装器。不要下载或单独运行内部 MSI、原始桌面 EXE、
Desktop API sidecar 或 agent EXE；公开 Release 只提供上述两个文件。

## 从 v0.5.4 升级前必读

`v0.5.4` 使用 Registry v7，而 `v0.6.0` 的正常资源工作流只接受 Registry v1。
升级前请先确认资源仓库中的本地修改已经提交并推送，并保留可以回退的 Git 历史。

- 首次连接旧 v7 仓库时，先在资源页打开“检查仓库”，审阅旧条目数、可从当前实体资源
  重建的条目数、将丢弃的条目数以及最终 YAML diff。
- 一次性替换只会依据仓库当前的实体资源目录重建 Registry v1；不会迁移旧外部引用、
  平台安装别名、Plugin 安装范围或其他 CC Port 专属元数据。
- 未确认前 CC Port 不会修改远端。如果计划显示将丢弃仍需保留的引用或设置，请不要应用；
  先从 Git 历史和现有配置中人工整理这些信息。
- `~/.claude/plugins` 现在被视为 Claude Marketplace/cache 运行时目录，只用于状态观察，
  不再作为可上传 Plugin 源码。升级后请重新扫描 Claude profile，并检查 Plugin 的分发方式和来源。

## 主要变化

### AI 自动调用与本机审批

- Windows 安装包现在同时包含桌面客户端、Desktop API sidecar 和独立的 `cc-port.exe`
  CLI/MCP agent；普通用户仍不需要安装 Python、Node.js 或 Rust。
- 在“设置 → AI 自动化”中，可以为一个精确的 Windows 原生 profile 审阅启用计划。
  批准后，CC Port 只安装随包发布的 `cc-port` Skill，并在该工具的原生配置中增加本机
  `cc-port.exe mcp --stdio` entry，不会删除桌面客户端或改写其他 MCP Server。
- 支持 MCP discovery、严格的单 JSON envelope 非交互 CLI，以及共享的
  `status → inventory → diff → plan → approval → apply → verify` 资源工作流。
- AI 的读取和计划可以自动执行；写计划必须出现在桌面的“待处理 AI 审批”中，由用户
  批准一次。审批绑定 operation、`plan_hash` 和完整 scope，会过期且只能消费一次；
  目标变化后旧审批不能授权新计划。

### Windows 与 WSL 独立 profile

- Windows 原生安装和每个 WSL 发行版使用独立、稳定的 profile id。Codex 和 Claude Code
  不会因为 `tool_id` 相同而合并本机实例或写入目标。
- profile 显式保存工具、环境种类、WSL 发行版、显示名和独立 home；WSL 停止或 UNC
  不可达时会标记 unavailable 并阻断写入，不会把不可达误判为资源缺失或删除请求。
- 配置、状态/备份目录、legacy 安装目标和任何 profile 的原生目标都不能与 Git 资源仓库
  相等或互为父子目录。

### Claude Code Instruction、Rule 与 Memory

- 新增用户级 `instruction` 和 Claude auto `memory` 资源工作流。Claude `CLAUDE.md`
  与 Codex `AGENTS.md` 只按各自工具的原生语义同步，不会自动互译。
- Claude Memory 作为精确 Markdown 目录快照处理；目录内全部 Markdown 都会执行疑似秘密
  扫描，ownership marker 保存在内容树之外。
- 默认 project-memory slot 使用不包含本机路径或用户名明文的哈希候选名。Windows 与 WSL
  slot 不会仅因内容相同而自动合并；下载到 projects 布局时需要各 profile 的本机映射。
- 配置的 Claude 用户 `rules_dir` 会递归发现 Markdown；当前只有可无损写回用户级目标的
  布局可以迁移，其他候选保持只读或阻断。

### Claude Code Skill 与 Plugin

- 同一个 Claude `skills_dir` 中，`<name>/SKILL.md` 被识别为普通 Skill；带
  `<name>/.claude-plugin/plugin.json` 的目录被识别为 `<manifest-name>@skills-dir`
  Plugin。Plugin 根或内部 `skills/*/SKILL.md` 不再重复显示为顶层 Skill。
- Claude 普通 Skill 的命令名来自目录名，不再强制要求其他工具使用的 `name` 或
  `description` frontmatter。
- skills-directory Plugin 以普通文件快照同步到目标用户 `skills_dir` 或已映射项目的
  `.claude/skills`，并对齐 `<plugin>@skills-dir` 的原生启用状态。
- Marketplace Plugin 只保存可移植引用；Marketplace 注册名与 Marketplace 来源分别保存和
  展示。需要安装时，CC Port 使用目标 profile 同一运行环境中的
  `claude plugin marketplace add/install`，并回读 Claude CLI 状态验证结果。
- 上传和下载会检查 manifest 名称、组件位置、自定义相对路径、JSON/Markdown 结构、链接、
  疑似秘密和内容指纹。CC Port 搬运 Plugin 时不会执行其中的脚本、Hook、MCP、LSP、
  Monitor 或 `bin` 内容。
- Claude `.claude-plugin/plugin.json`、JSON 状态和 CLI 不会用于 Codex；Codex
  `.codex-plugin/plugin.json`、TOML 状态和安装流程继续保持独立。

### Registry v1 与仓库检查

- `registry.yaml` 现在只保存工具中立的 `(kind, name)` 以及互斥的仓库相对 `path` 或外部
  `source`。派生元数据、本机 profile、用户目录、目标路径和运行状态不会进入 Registry。
- 可选的 `cc-port.yaml` 保存平台/工具 allowlist、安装别名和 Plugin 安装意图；其他工具
  无需理解该文件。
- 远端刷新会在同一个 commit 上只读审计 Registry。桌面“检查仓库”会展示问题、默认选择和
  最终 YAML diff；修复只提交 `registry.yaml`，不会移动、改写或删除资源内容，也不会修改
  `cc-port.yaml`。
- Registry 缺失、损坏、为链接或 overlay 无效时，本地扫描仍可使用，但依赖远端清单的上传
  和安装会 fail closed。

### 桌面信息更清晰

- Plugin 列表、详情和批量计划现在显示人类可读的平台与分发方式，例如
  “Claude Code · Skills 目录插件（@skills-dir）”和“Claude Code · Marketplace 插件”。
- Claude Marketplace 名称、可移植来源和版本策略分字段编辑；切换来源类型时会清除不再适用
  的旧字段。
- 删除对话框显示本地化的平台、作用域和操作说明，不再暴露内部 track、scope 或 method 枚举。
- 说明页增加项目仓库与 GitHub Star 支持入口。

## Public Beta 限制

- 安装器尚未做 Authenticode 签名。Windows SmartScreen 可能显示“未知发布者”；请核对下载
  域名和 `SHA256SUMS.txt` 后，通过“更多信息”继续。
- 当前没有自动更新，仅正式提供 Windows 10/11 x64 桌面安装器；目标电脑仍需 Git for Windows
  和 Git Credential Manager。
- AI 自动引导当前只支持 Windows 原生 profile。WSL profile 的现有资源 inventory、plan 和
  apply 能力保留，但不会用 Windows 进程伪装 WSL MCP 连接成功。
- AI 审批是应用层工作流控制，不是操作系统级的人类在场证明。AI 宿主仍需限制 agent 直接修改
  CC Port 状态目录或伪造桌面 sidecar 调用。
- Claude Marketplace 自动安装要求目标 profile 同一运行环境中存在可用的 Claude CLI，并且
  引用包含可移植来源；Windows 与 WSL CLI 不能互相借用。managed scope 只读，project/local
  scope 需要已保存的精确项目映射。
- Claude content Plugin 同步只支持带 `.claude-plugin/plugin.json` 的 skills-directory Plugin；
  没有 manifest 的 `--plugin-dir` 源码不会被当作可同步 content。项目 Plugin 仍受 Claude
  workspace trust 和组件权限控制，变更后可能需要重启 Claude Code 或执行 `/reload-plugins`。
- 每个 Claude profile 当前只解析一个显式用户级 `settings_path`，不会自动合并 managed policy、
  受信任后生效的 project/local settings 或临时 `--settings` 来源。
- Claude 项目级 Instruction 和项目 Rule 仍只读；嵌套用户 Rule 在整理为明确可移植布局前保持
  阻断。Claude auto Memory 不会安装为 Codex 资源。
- WSL LX 符号链接仍会阻断对应资源；Windsurf 和 OpenCode 平台预设仍为实验性。

## 升级

结束正在执行的写操作后，运行 `v0.6.0` 安装器覆盖升级。安装器不会删除你的资源仓库、
AI 工具原生目录中的资源，或 CC Port 本机状态、备份和操作历史。升级后先审阅 Registry v1
检查结果，再重新扫描每个 Windows/WSL profile；如需 AI 自动调用，请在“设置 → AI 自动化”
中审阅并批准对应的 Windows profile 启用计划。
