# 统一资源清单与批量双向同步规格

> [FRAME] 桌面端固定状态、提示、警告与错误的语言边界和消息协议以
> [桌面端国际化规格](desktop-i18n.md) 为准。置信度：HIGH。

## 目标

桌面端只保留一张资源清单，并以资源页作为默认首页和唯一资源入口。清单合并私有资源
仓库的只读远端快照和本机 AI 工具原生目录中的实例，使用 `kind:name` 作为逻辑资源身份。GitHub 引用收集、
任意本地目录导入、环境发现、单项同步、批量同步和换机恢复不再使用独立页面或独立领域模型。

## 领域边界

- 远端资源仓库是跨设备事实源；跨设备共享的资源内容、引用与元数据以其配置分支的提交为准。
- 受管远端镜像是 LPM 隐藏维护的完整派生缓存，可被丢弃并从远端重建。它不是用户可编辑工作区，不向 AI 工具暴露，也不作为第三份事实源。
- 远端快照是由 commit 标识、从受管远端镜像派生的只读视图；清单、比较和计划都引用明确的快照提交。
- 本地实例只存在于 AI 工具原生目标中。工具不链接受管远端镜像；安装、卸载、备份和回滚继续在工具目标边界内执行。
- “刷新远端”只检查远端引用并更新受管远端镜像与远端快照，不扫描或写入 AI 工具目录。
- “扫描本地”只在显式范围内发现本地实例，不 fetch、不修改远端引用，也不写入远端资源仓库。
- “上传到仓库”从选中的本地实例生成并确认计划后写远端；“安装到工具”从选中的远端资源生成并确认计划后写 AI 工具目标。
- 桌面主流程不创建用户需要维护的本地 Git 工作区，不调用旧 `resource_pull`，不提供仓库级“一键更新全部”，也不定时轮询远端。

## 清单

- `asset_inventory` 每个逻辑资源只返回一行；平台级实例放在 `local_instances` 中。
- 未执行本地扫描时，本地状态必须是 `unknown`，不得推断为 `missing`。
- 显式扫描后，清单是远端资源与所有发现到的本地资源的并集。
- 远端存在时使用远端描述作为主描述；仅本地存在时使用本地解析描述；差异保留在详情中。
- 本地状态为 `unknown`、`missing`、`single`、`identical-copies` 或 `variants`。
- 远端状态为 `present`、`missing`、`read-only` 或 `unavailable`。
- 聚合状态沿用 `local-only`、`remote-only`、`same`、`content-different`、
  `metadata-only`、`target-conflict` 和 `uncomparable`。
- 多个平台中的本地副本指纹相同时折叠为同一内容版本；指纹不同时必须保留所有实例。
- 插件使用双轨清单：自有源码为 `content`，第三方 marketplace、npm、cache 和 managed 插件为 `reference`。
- 插件实例额外显示平台、来源、版本策略、观测版本、作用域、项目身份、启用状态和可写性；cache 路径不得成为上传源。
- 不同平台或来源的同名插件默认分开；同平台同来源的多作用域实例聚合到一行。

## 清单采集契约

桌面端继续复用 `asset_inventory`，不新增接口或修改响应结构：

- 应用启动时静默执行一次 `refresh_remote=true`；尚未扫描本地时同时传入 `scan_local=false`。同一应用会话内不得再次自动刷新，也不得启动轮询。
- 用户点击“刷新远端”时执行相同的远端刷新。若本次会话已经扫描本地，则同时传入 `scan_local=true` 及最近一次精确的 `scan_global`、`project_ids`，保证刷新后的清单仍是同一范围内的双端并集。
- 用户点击“扫描本地”时传入 `scan_local=true`、`refresh_remote=false` 及弹窗确认的范围；成功响应中的实际扫描范围保存为会话状态，应用重启后回到“未扫描”。
- 远端刷新与本地扫描是两个独立的会话级后台任务，可以同时运行；手动操作、自动刷新或任务重试遇到同一来源已有任务时，必须加入并复用当前 Promise，不得重复请求 `asset_inventory` 或重复发布清单。扫描弹窗提交范围后立即关闭，进度、成功和失败继续由任务中心跟踪。
- `asset_inventory` 同时需要远端快照和本地发现时并行执行两侧读取，待两侧都完成后再统一构建逻辑资源和 diff。
- 任一来源任务成功后立即发布一次完整清单。若请求期间另一侧已有更新完成，则先以另一侧最新完成的扫描范围重新构建 diff，旧响应不得覆盖较新的安装状态；两个重叠任务先后完成时必须产生两次清单更新。
- 配置或资源变更发生在远端刷新期间时，桌面端必须记录一次待刷新状态；当前任务结束后自动执行一次静默远端刷新，同一轮内的多次变更合并为一次。若补刷期间再次发生变更，则补刷结束后继续安排下一轮，直至发布的最终清单对应最后一次变更。
- 启动刷新不弹成功提示；手动刷新通过任务中心区分“已是最新”“已获取新版本”和“远端不可用，正在显示缓存”。
- 未配置仓库时返回可引导至设置页的状态；远端不可用时可继续展示已有缓存，但缓存只读，依赖远端验证的上传或安装继续按现有规则阻断。
- 远端按钮只受远端任务 busy 状态约束，本地按钮只受本地任务 busy 状态约束；任一清单任务运行时，仍禁用依赖当前清单生成计划或执行写入的页面操作。

## 批量计划

`asset_batch_plan` 只接受资源身份、同步方向、目标平台和用户决策，不接受可信路径。
服务端根据最新远端快照与本地扫描重新推导路径、指纹、所有权、兼容性和可写性。

- 上传方向：本地缺失、内容相同、创建远端、覆盖远端、重命名上传、跳过或阻断。
- 下载方向：远端缺失、内容相同、创建本地、覆盖本地、重命名安装、跳过或阻断。
- 混合选择中的不适用项必须返回 `skip` 及原因，不能静默移除。
- 同一资源存在不同本地版本时，上传必须携带 `local_instance_id`；未选择时阻断；分别重命名上传时允许为同一资源提交多条来源选择，但目标名称不得重复。
- 未管理本地目标只有在计划中显式记录覆盖确认后才允许下载覆盖。
- 下载目标平台由批次统一选择；未启用、不兼容或无法解析目标路径的平台返回跳过或阻断。
- 计划按 `create`、`update`、`rename`、`unchanged`、`skip`、`manual`、`blocked` 分类。
- 插件上传计划明确区分“上传内容”和“保存引用”；未确认归属的直接本地源码必须选择 content、reference 或 skip。
- 插件引用下载只对齐已安装可写实例的启用状态；缺失或 managed 实例返回 `manual` 指引，不复制 cache。
- 扫描结果没有可靠 selector 时保留远端声明策略；`observed_version` 不参与策略替换，marketplace 本地绝对路径不进入注册表。
- 规范化计划计算 `plan_hash`，其中包含远端提交、资源断言、源指纹、目标指纹和用户决策。

## 批量执行

`asset_batch_apply` 接收与计划相同的请求和预期 `plan_hash`。执行前必须重新生成完整计划；
哈希变化时返回 `stale-plan` 和最新计划，不执行任何写入。

- 上传先逐项验证并准备安全内容，再把所有可执行远端变更合并为一次提交和普通推送。
- 无关远端提交允许在最新提交上重放一次；目标资源变化时该资源转为过期，不得覆盖。
- 最终推送失败时，所有已准备上传项统一失败，不能报告部分远端成功。
- 下载按“资源 × 平台”使用独立 `LocalChangeTransaction`；单项失败后继续其他项目。
- 批次不持久化，不提供跨应用重启恢复；已完成本地事务与远端提交继续使用现有审计机制。
- 单项计划与执行接口保留，内部委托给同一资产规则，不维护第二套写入语义。
- 仅含手工项的插件恢复返回 `needs-action`；手工项与成功写入并存时返回 `partial`，不得静默报告成功。

## 桌面交互

- 桌面窗口默认尺寸为 `1360×820`，最小尺寸为 `1280×720`；低于最小尺寸时由 Tauri 窗口约束阻止继续缩小，不提供资源页窄屏堆叠模式。
- 全局侧栏固定为 `220px`。资源页在剩余工作区内保持“资源清单 + 详情”双栏：详情宽度限制在 `320px` 至 `420px`，窗口增加的空间主要分配给资源清单。
- 应用外层固定为视口高度且不承担页面滚动。资源表与资源详情分别在各自剩余高度内滚动；设置页和说明页使用各自的单一内容滚动区。
- 删除环境页、不可达同步页和添加页的发现模式。
- 删除概览页和独立添加资源页；应用首次启动直接进入资源页，概览统计不迁移。
- 全局顶栏显示当前页面名称，只保留任务中心和语言切换；不显示 `registry_path`，也不提供无文字的全局刷新图标。
- 资源页不保留总括性的“添加资源”按钮。页头下方并排显示远端与本地两个紧凑状态区，并分别提供“刷新远端”和“扫描本地”；每个状态区按标题、元数据、操作按钮分层，按钮不得与元数据共享挤压列。
- 远端状态区显示仓库、分支、短 commit、上次检查时间及“在线”“使用缓存”或“未配置”；本地状态区显示“未扫描”，或最近扫描发现的工具数和实例数。
- 两个来源状态区下方显示单行“收集与导入”操作区，左侧解释 GitHub 引用与本地内容导入的差异，右侧以“从 GitHub 收集”为主按钮、“导入本地目录”为次按钮；操作区不得挤占侧栏或详情宽度。
- 关键词搜索覆盖名称、`kind:name` 资源键和描述；类型与总体状态筛选常驻，本地状态、远端状态和工具筛选折叠到“更多筛选”，显示活动条件数量并可一次清除。
- 表头复选框只选择当前可见资源；跨筛选的已选资源保留。存在选择时显示上下文操作栏，包含总选中数、被筛选隐藏数、“上传到仓库”“安装到工具”和“清除选择”。
- “从 GitHub 收集”和“导入本地目录”分别打开专用弹窗，不提供模式切换；两个弹窗各自维护草稿，并复用相同的推送开关、任务反馈和未保存关闭确认。
- “扫描本地”打开扫描弹窗，可选择全局范围和已保存项目，并可通过目录选择器新增项目根；确认后弹窗立即关闭，扫描在后台继续。
- 无 Git remote 的项目标记为仅观察；project/local 插件通过 Git remote 与仓库内相对路径跨机器映射。
- 桌面端不提供手工“插件引用”入口；后端与 CLI 的 `plugin_reference_add` 保持兼容，扫描后上传计划中的“保存引用”仍是桌面端插件引用主流程。
- 本地导入接受可编辑路径，并可通过系统目录选择器填写；名称与类型覆盖放在折叠的高级设置中。
- 收集和导入默认推送私有资源仓库，但必须显示可关闭的“完成后推送”开关。
- 仓库未配置、远端不可用、存在遗留写入阻断、清单尚未加载或正在刷新时，收集与导入入口保持可见但禁用，并就地显示阻断原因；未配置时提供设置入口，远端不可用时提供刷新入口。
- 有未提交内容时，关闭任一弹窗必须二次确认；成功后关闭弹窗、重置筛选、清空批量选择、刷新清单并定位新资源。
- 资源表格列为选择、资源、描述和状态。状态列只显示现有精确总体状态；本地状态和远端状态保留在详情中。列表描述最多显示两行，完整描述在详情中显示。
- 资源详情按“标题与总体状态、警告与阻断、差异摘要与描述比较、来源与同步、本地实例、危险操作”排序；删除插件等危险操作必须位于详情底部。
- “上传到仓库”和“安装到工具”只在至少选择一个资源后可用；两者都先展示计划，所有冲突解决且存在可执行项后才能确认。
- 安装前展示全部支持工具；只有已启用工具可选，未启用工具提供设置入口。
- 页面切换时运行中任务继续由会话级任务中心跟踪，但关闭应用后不恢复批次。
- 删除插件先展示实例级卸载计划；managed 不可选择，任何卸载失败或手工待办都会保留远端记录。

## CLI 与兼容边界

- 新增 `lpm asset upload` 和 `lpm asset download`，支持多资源、`--all`、重复
  `--platform`、`--choices`、`--dry-run`、`--yes` 和 `--json`。
- 新增 `lpm plugin project add|list|remove`、`lpm plugin reference add` 和
  `lpm plugin delete`；桌面与 CLI 使用相同插件计划和校验。
- 删除 `lpm env` 命令与全部 `env_*` Desktop API。
- 不新增 `lpm migrate` 或新的 ZIP 迁移格式。
- 旧 `resource_pull`、`local_path` 与仓库级同步端点只保留兼容，不得被新的桌面资源流程调用或展示。
- 内部仍可保留工具和 MCP 发现能力，但不得继续暴露环境采集、仓库级环境差异或环境部署入口。

## 验收标准

- 应用默认以 `1360×820` 打开，不能缩小到 `1280×720` 以下；最小尺寸下来源状态区不重叠、筛选操作完整、状态标签不逐字换行、资源表不产生横向溢出。
- 资源页外层不出现滚动条，资源表和详情可独立纵向滚动；设置页与说明页仍能通过各自的单一内容滚动区访问全部内容。
- 宽屏下侧栏保持 `220px`，详情不超过 `420px`，新增宽度主要进入资源清单；长名称、描述和路径不得撑破容器。
- 一次本地扫描后，远端独有、本地独有和两端共有资源均只出现一条逻辑资源行。
- 应用启动只自动刷新远端一次，停留期间不轮询；手动刷新能区分提交不变、提交变化和缓存降级。
- “刷新远端”不写 AI 工具目录，“扫描本地”不 fetch 或写远端；扫描后刷新会复用相同会话扫描范围，本地独有行不会消失。
- 用户可在远端刷新运行时启动本地扫描，也可在本地扫描运行时启动远端刷新；两个任务分别完成时，安装状态按完成顺序刷新两次，后完成的旧请求不得回退较新的扫描结果。
- 同来源的手动操作、自动刷新和任务重试重叠时只执行一次 `asset_inventory` 并只发布一次结果；共享任务结束前 busy 状态不得被任一加入者提前解除。
- 远端刷新期间发生一次或多次配置、资源变更时，当前任务结束后只补刷一次；补刷期间的新变更继续触发下一轮，最终清单不得丢失最后一次变更。
- 应用首次启动直接显示资源页；侧栏不再出现概览或独立添加资源入口。
- 用户可从资源页独立的“从 GitHub 收集”和“导入本地目录”入口登记资源；页面不出现总括性的“添加资源”按钮、模式标签或手工插件引用表单。
- 仓库未配置、远端不可用、存在遗留写入阻断、清单尚未加载或正在刷新时，收集与导入按钮保持可见但不可执行，并提供对应原因与可用的配置或刷新引导。
- 收集或导入成功后，清单定位到新增的 `kind:name`。
- 用户可查看主描述、双端状态，并在详情中定位每个本地实例及其差异。
- 搜索、折叠筛选和可见项全选不清除隐藏选择；上下文操作栏准确显示总选中数与隐藏选中数。
- 任意单选或多选都可生成上传到仓库或安装到工具的计划，不适用项有明确跳过原因；未选择资源时不显示这两个动作。
- 安装可在批次级选择一个或多个已启用 AI 工具，并按兼容性生成目标。
- 计划过期、未管理覆盖、多本地版本和远端竞争均不会导致静默覆盖。
- 远端不可用时缓存只供查看，依赖远端验证的写入继续阻断。
- 普通资源界面不出现本地仓库路径、dirty、ahead、diverged 或 Git worktree 概念，也没有“一键更新全部”。
- Codex 和 Claude marketplace cache 永不上传；opencode npm 声明只保存包和 selector。
- 同步缺失的第三方插件时提供可复制安装指引，不直接操作未公开缓存布局。
