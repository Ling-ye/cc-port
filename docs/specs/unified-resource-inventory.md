# 统一资源清单与批量双向同步规格

## 目标

桌面端只保留一张资源清单，并以资源页作为默认首页和唯一资源入口。清单合并私有资源
仓库和本机 AI 工具目录中的资产，使用 `kind:name` 作为逻辑资源身份。GitHub 引用收集、
任意本地目录导入、环境发现、单项同步、批量同步和换机恢复不再使用独立页面或独立领域模型。

## 清单

- `asset_inventory` 每个逻辑资源只返回一行；平台级实例放在 `local_instances` 中。
- 未执行本地扫描时，本地状态必须是 `unknown`，不得推断为 `missing`。
- 显式扫描后，清单是远端资源与所有发现到的本地资源的并集。
- 远端存在时使用远端描述作为主描述；仅本地存在时使用本地解析描述；差异保留在详情中。
- 本地状态为 `unknown`、`missing`、`single`、`identical-copies` 或 `variants`。
- 远端状态为 `present`、`missing`、`read-only` 或 `unavailable`。
- 聚合状态沿用 `local-only`、`remote-only`、`same`、`content-different`、
  `metadata-only`、`target-conflict` 和 `uncomparable`。
- 多个平台中的本地副本指纹相同时折叠为同一内容版本；指纹不同时必须保留所有实例。
- 插件使用双轨清单：自有源码为 `content`，第三方 marketplace、npm、cache 和 managed 插件为 `reference`。
- 插件实例额外显示平台、来源、版本策略、观测版本、作用域、项目身份、启用状态和可写性；cache 路径不得成为上传源。
- 不同平台或来源的同名插件默认分开；同平台同来源的多作用域实例聚合到一行。

## 批量计划

`asset_batch_plan` 只接受资源身份、同步方向、目标平台和用户决策，不接受可信路径。
服务端根据最新远端快照与本地扫描重新推导路径、指纹、所有权、兼容性和可写性。

- 上传方向：本地缺失、内容相同、创建远端、覆盖远端、重命名上传、跳过或阻断。
- 下载方向：远端缺失、内容相同、创建本地、覆盖本地、重命名安装、跳过或阻断。
- 混合选择中的不适用项必须返回 `skip` 及原因，不能静默移除。
- 同一资源存在不同本地版本时，上传必须携带 `local_instance_id`；未选择时阻断；分别重命名上传时允许为同一资源提交多条来源选择，但目标名称不得重复。
- 未管理本地目标只有在计划中显式记录覆盖确认后才允许下载覆盖。
- 下载目标平台由批次统一选择；未启用、不兼容或无法解析目标路径的平台返回跳过或阻断。
- 计划按 `create`、`update`、`rename`、`unchanged`、`skip`、`manual`、`blocked` 分类。
- 插件上传计划明确区分“上传内容”和“保存引用”；未确认归属的直接本地源码必须选择 content、reference 或 skip。
- 插件引用下载只对齐已安装可写实例的启用状态；缺失或 managed 实例返回 `manual` 指引，不复制 cache。
- 扫描结果没有可靠 selector 时保留远端声明策略；`observed_version` 不参与策略替换，marketplace 本地绝对路径不进入注册表。
- 规范化计划计算 `plan_hash`，其中包含远端提交、资源断言、源指纹、目标指纹和用户决策。

## 批量执行

`asset_batch_apply` 接收与计划相同的请求和预期 `plan_hash`。执行前必须重新生成完整计划；
哈希变化时返回 `stale-plan` 和最新计划，不执行任何写入。

- 上传先逐项验证并准备安全内容，再把所有可执行远端变更合并为一次提交和普通推送。
- 无关远端提交允许在最新提交上重放一次；目标资源变化时该资源转为过期，不得覆盖。
- 最终推送失败时，所有已准备上传项统一失败，不能报告部分远端成功。
- 下载按“资源 × 平台”使用独立 `LocalChangeTransaction`；单项失败后继续其他项目。
- 批次不持久化，不提供跨应用重启恢复；已完成本地事务与远端提交继续使用现有审计机制。
- 单项计划与执行接口保留，内部委托给同一资产规则，不维护第二套写入语义。
- 仅含手工项的插件恢复返回 `needs-action`；手工项与成功写入并存时返回 `partial`，不得静默报告成功。

## 桌面交互

- 删除环境页、不可达同步页和添加页的发现模式。
- 删除概览页和独立添加资源页；应用首次启动直接进入资源页，概览统计不迁移。
- 资源页工具栏固定为“添加资源”“扫描本地”“上传所选”“下载所选”；“添加资源”为次要操作，“下载所选”保持主操作。
- “添加资源”打开弹窗，默认使用“GitHub 收集”，并提供“本地导入”；两种模式在弹窗会话内分别保留草稿。
- “扫描本地”打开扫描弹窗，可选择全局范围和已保存项目，并可通过目录选择器新增项目根。
- 无 Git remote 的项目标记为仅观察；project/local 插件通过 Git remote 与仓库内相对路径跨机器映射。
- “添加资源”额外提供“插件引用”模式，按 Codex、Claude Code、opencode 展示 marketplace、npm 或 Git 来源字段。
- 本地导入接受可编辑路径，并可通过系统目录选择器填写；名称与类型覆盖放在折叠的高级设置中。
- 收集和导入默认推送私有资源仓库，但必须显示可关闭的“完成后推送”开关。
- 有未提交内容时，关闭弹窗必须二次确认；成功后关闭弹窗、重置筛选、清空批量选择、刷新清单并定位新资源。
- 资源表格列为选择、资源、描述、本地状态、远端状态和总体差异，详情显示平台实例与路径。
- 过滤后的全选只选择当前可见资源；跨过滤选择必须保留。
- 上传和下载都先展示计划，所有冲突解决且存在可执行项后才能确认。
- 下载前展示全部支持工具；只有已启用工具可选，未启用工具提供设置入口。
- 页面切换时运行中任务继续由会话级任务中心跟踪，但关闭应用后不恢复批次。
- 删除插件先展示实例级卸载计划；managed 不可选择，任何卸载失败或手工待办都会保留远端记录。

## CLI 与兼容边界

- 新增 `lpm asset upload` 和 `lpm asset download`，支持多资源、`--all`、重复
  `--platform`、`--choices`、`--dry-run`、`--yes` 和 `--json`。
- 新增 `lpm plugin project add|list|remove`、`lpm plugin reference add` 和
  `lpm plugin delete`；桌面与 CLI 使用相同插件计划和校验。
- 删除 `lpm env` 命令与全部 `env_*` Desktop API。
- 不新增 `lpm migrate` 或新的 ZIP 迁移格式。
- 内部仍可保留工具和 MCP 发现能力，但不得继续暴露环境采集、仓库级环境差异或环境部署入口。

## 验收标准

- 一次本地扫描后，远端独有、本地独有和两端共有资源均只出现一条逻辑资源行。
- 应用首次启动直接显示资源页；侧栏不再出现概览或独立添加资源入口。
- 用户可从资源页收集 GitHub 引用或导入任意本地目录，成功后清单定位到新增的 `kind:name`。
- 用户可查看主描述、双端状态，并在详情中定位每个本地实例及其差异。
- 任意单选或多选都可生成上传或下载计划，不适用项有明确跳过原因。
- 下载可在批次级选择一个或多个已启用 AI 工具，并按兼容性生成目标。
- 计划过期、未管理覆盖、多本地版本和远端竞争均不会导致静默覆盖。
- Codex 和 Claude marketplace cache 永不上传；opencode npm 声明只保存包和 selector。
- 同步缺失的第三方插件时提供可复制安装指引，不直接操作未公开缓存布局。
