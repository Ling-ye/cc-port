# 桌面端国际化规格

## 范围

- [FRAME] 桌面端全部生产组件支持简体中文与英文；默认语言、本地存储键和语言切换入口保持不变。置信度：HIGH。
- [FRAME] LPM 定义的固定标题、状态、提示、警告、阻断、计划原因、结果和错误摘要必须翻译。置信度：HIGH。
- [FRAME] 资源名称与描述、路径、URL、版本、提交、品牌名、技术枚举以及 Git、GitHub、操作系统等外部诊断原文不翻译。置信度：HIGH。
- [FRAME] CLI 与 MCP Server 不读取桌面语言，也不改变现有文本或机器 JSON 输出。置信度：HIGH。

## 消息契约

- [FRAME] Desktop API 使用 `UiMessageRef` 描述固定消息：`code` 是稳定语义代码，`params` 是插值参数，`fallback` 是兼容英文文本。置信度：HIGH。
- [FRAME] 固定消息必须在业务判断产生处同时创建消息引用与兼容文本；禁止根据英文原句反查消息代码。置信度：HIGH。
- [FRAME] 数组文本字段增加对应的 `*_refs`，标量文本字段增加对应的 `*_ref`；旧字符串字段在兼容期继续返回。置信度：HIGH。
- [FRAME] 前端优先渲染消息引用；已知代码使用当前语言词典，未知代码使用 `fallback`，无 `fallback` 时使用本地化通用错误。置信度：HIGH。
- [FRAME] 外部诊断可以作为插值参数保留原文，但 LPM 自己定义的摘要和操作建议仍使用当前语言。置信度：HIGH。
- [FRAME] CLI 的机器 JSON 序列化边界移除桌面专用的 `*_ref` 与 `*_refs` 字段，CLI 和 MCP 契约不因桌面翻译元数据发生变化。置信度：HIGH。

## 生命周期

- [FRAME] 当前页面中的消息引用随语言切换重新渲染。置信度：HIGH。
- [FRAME] 任务中心在任务创建或结束时把消息解析为当时语言的字符串；之后切换语言不改写已有任务记录。置信度：HIGH。
- [FRAME] 旧 Desktop API 文本字段本次只标记兼容弃用，不在本规格中承诺删除版本。置信度：HIGH。

## 质量门禁

- [FRAME] TypeScript 编译必须保证中英文键集合一致。置信度：HIGH。
- [FRAME] 自动测试必须保证同一翻译键的插值占位符一致，并保证每个受支持的消息代码映射到有效翻译键。置信度：HIGH。
- [FRAME] 生产 TSX 的用户可见固定字面量必须通过静态审计；品牌名、技术值和示例语法只能通过带理由的显式白名单放行。置信度：HIGH。
- [FRAME] 后端测试必须同时验证消息代码、参数、兼容文本和未知消息回退。置信度：HIGH。

## 验收

- [FRAME] 本地独有资源在中文界面显示“本地内容不存在于远端仓库中。”，英文界面显示 “Local content is not present in the remote repository.”。置信度：HIGH。
- [FRAME] 资源差异、计划、插件删除、设置诊断、操作结果和桥接固定错误均不得依赖英文原句完成翻译。置信度：HIGH。
- [FRAME] 动态资源描述和外部诊断在两种语言下保持原值，不进入翻译词典。置信度：HIGH。
