# 操作历史与手动恢复规格

## 目标

用户可以查看所有持久化本地写操作，并显式把成功操作影响的目标恢复到该操作之前的状态。

## 历史记录

- 历史来自本机状态目录 `operations/*.json`，不写入资源 Git 仓库。
- 默认按开始时间倒序返回。
- 每条记录展示操作 ID、类型、状态、开始/结束时间、消息、目标数量和实际变更数量。
- 只有状态为 `succeeded` 且类型属于环境部署、资源安装或资源卸载的记录可以恢复。

## 恢复语义

- 恢复本身创建新的 `operation-restore` 操作记录。
- 恢复前先快照目标当前状态，因此恢复失败时可以回滚恢复动作。
- 默认要求目标当前哈希等于原操作完成后的哈希；发生漂移时拒绝恢复。
- 用户显式选择 `force` 后可以覆盖漂移目标。
- 原操作前不存在的目标在恢复时删除；原操作前存在的目标从该操作的备份恢复。
- 备份路径必须位于 `backups/<source-operation-id>` 内，禁止读取任意外部备份路径。
- 恢复与普通安装、卸载使用相同的目标路径跨进程锁；无法在超时内获取锁时不开始恢复。

## 验收标准

- 历史查询不会修改任何目标。
- 恢复成功后每个目标的哈希等于原操作记录的 `before_hash`。
- 存在漂移且未指定 `force` 时不写入任何目标。
- 恢复中途失败时恢复动作自身回滚，目标保持恢复开始前状态。
