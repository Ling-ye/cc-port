# 简化设置页：原生 Git 仓库连接

## 目标

设置页只负责两件事：连接用户提供的资源仓库，并选择接收资源的 AI 工具。GitHub 登录、OAuth 状态、账号信息、Token 管理和仓库管理不属于桌面设置页。

## 页面行为

- 点击设置导航后必须立即渲染完整页面结构，不得等待任何桌面 API 响应后才显示仓库、目标工具或诊断区域。
- 页面加载时并行读取 `config_get` 与 `git_credential_status`，不触发登录。
- 初始读取期间页面和仓库区域标记为忙碌；仓库操作、平台开关和诊断按钮保持禁用，五个目标工具使用中性开关占位。
- 设置页不预加载、不跨导航缓存数据，也不改变 sidecar 生命周期；离开后重新进入仍重新读取两个接口并显示完整加载布局。
- 仓库卡片解释必须粘贴完整 HTTPS 仓库根链接；GitHub 主页链接不是有效输入。
- 主按钮固定为“连接并验证仓库”；处理中显示明确进度文案。
- Git/GCM 未就绪时显示原因和官方安装入口，但不静默禁用主按钮。用户点击主按钮仍得到同一结构化错误。
- 首次验证可由 GCM 打开系统浏览器；应用自身没有 OAuth 等待、轮询或取消界面。
- 替换已绑定仓库前保留确认步骤和并发保护。
- 读写验证成功后显示规范化 URL、默认分支和远端是否为空。
- 诊断区域继续按需调用 `doctor`；Git/GCM 前提状态直接显示在仓库卡片中。

## 接口

- `config_get` 只返回桌面可编辑/展示配置，不返回 Token 来源或 Token 掩码。
- `git_credential_status` 返回：
  - `state`: `ready`、`git_missing`、`gcm_missing` 或 `gcm_not_configured`
  - `ready`
  - Git 路径、来源和版本
  - GCM 版本
  - 生效的 `credential.helper` 列表
  - 用户可读诊断详情和官方安装链接
- `config_bind_repo` 保留现有响应结构；桌面边界增加 HTTPS-only 与 Git/GCM 前提校验。

## 失败恢复

- `config_get` 或 `git_credential_status` 任一失败时按整页读取失败处理，不展示部分成功结果；保留完整布局并禁用修改操作。
- 读取失败同时显示页面内错误与全局错误横幅；页面内“重试”重新并行调用两个读取接口。
- 当前挂载期间已有成功数据时，刷新失败可继续展示旧数据，但重试成功前不得基于旧数据执行修改。
- 登录取消：提示登录已取消，按钮保持可重试。
- 凭据失效：提示需要重新登录，再次点击主按钮重新执行交互式验证。
- 无写权限：说明读取成功但缺少写权限，不保存绑定。
- Git/GCM 缺失或未配置：说明具体前提并提供安装/配置文档入口。
- 网络超时：说明读取或写入验证超时，不保存绑定。
- 任何错误均不得包含 URL userinfo、Token、认证头或子进程环境值。
