# 孤立备份生命周期规格

## 目标

为 `backups/` 中没有对应合法操作记录的条目提供可审计的检查、导出、隔离和最终删除流程，同时避免普通保留策略误删未知恢复数据。

## 状态定义

- `orphan`：位于 `backups/` 直接子级，且 `operations/<name>.json` 不存在。
- `quarantined`：用户显式确认后移动到 `maintenance/orphans/<quarantine-id>/` 的孤立备份。
- `deleted`：用户对隔离批次再次显式确认后完成物理删除。

## 检查与导出

- 检查只枚举 `backups/` 的直接子级，不跟随符号链接。
- 每个条目展示名称、类型、字节数和最后修改时间。
- 导出前必须在锁内重新确认条目仍是孤立备份。
- ZIP 导出不得跟随目录中的符号链接；符号链接以链接元数据写入归档。
- 默认导出目录位于本机状态目录 `exports/orphans/`，不得写入私有资源 Git 仓库。

## 隔离与删除

- 隔离必须由用户显式选择一个或多个孤立备份。
- 隔离时获取维护锁、备份路径锁和潜在操作记录路径锁，并重新确认孤立状态。
- 隔离使用同一文件系统内的原子移动，不复制后删除。
- 隔离批次写入 manifest 和独立维护审计记录。
- 物理删除只接受合法隔离批次 ID，不允许直接删除 `backups/` 中的孤立条目。
- 删除隔离批次后写入独立维护审计记录；删除失败不得报告已回收空间。

## 验收标准

- 普通 retention prune 不删除孤立备份。
- 导出和隔离不跟随符号链接。
- 在检查后新建同名操作记录时，隔离必须被重新验证并阻止。
- 隔离后原 `backups/<name>` 不存在，隔离 manifest 可查询。
- 最终删除需要独立确认，并产生可查询审计。
