# 资源提交策略规格

## 目标

LPM 提交和推送的是受管理 AI 资源，不是资源仓库中任意文件。提交前必须能够说明资源级变化并阻断敏感内容。

## 管理范围

允许自动提交的路径：

- `registry.yaml`
- `profiles/`
- `secrets.example.yaml`
- `skills/`
- `rules/`
- `prompts/`
- `mcp/`
- `plugins/`
- `resources/`
- `.claude-plugin/plugin.json`
- LPM 生成的根目录 `README.md`

其他路径属于非管理路径，默认阻断自动提交。

## 提交计划

- 提交前生成 `ResourceCommitPlan`。
- 计划包含新增、修改、删除路径，资源级变化、阻断项、敏感内容发现和建议提交消息。
- 只暂存计划列出的管理路径，不使用 `git add -A`。
- 用户可以修改提交消息，但不能通过修改消息绕过阻断。

## 敏感内容

- 工作区提交前扫描即将提交的管理文件。
- push 前扫描本地相对远端新增的所有提交内容。
- 真实 `.env`、私钥、token、API key、密码和高风险凭据模式阻断提交或推送。
- `secrets.example.yaml` 和 `${NAME}` 占位符允许提交。

## 验收标准

- 非管理文件不会被暂存或自动提交，并产生明确阻断信息。
- 管理路径中的正常资源变更可以提交。
- 已经手工提交但尚未推送的敏感内容会阻断 push。
- 提交计划以资源名称和类型描述变化，不要求用户理解 Git 暂存区。
