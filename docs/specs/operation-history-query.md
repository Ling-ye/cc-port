# 操作历史查询与维护审计规格

## 目标

在操作记录增长后仍能稳定浏览历史，并允许用户按需查看单条目标详情和状态维护审计。

## 操作历史

- 历史列表使用服务端分页，默认每页 20 条，单页上限 100 条。
- 列表项只返回摘要，不包含全部 target 数组。
- 响应包含总数、偏移量、页大小和是否还有下一页。
- 单条详情按 operation id 查询，返回 metadata、target 和可恢复状态。
- 恢复动作仍以详情对应的最新持久记录为准，不信任列表缓存。

## 维护审计

- `maintenance/*.json` 是维护审计事实源，临时 `trash/` 和隔离目录不作为审计记录。
- 审计列表按创建时间倒序返回摘要，并支持数量限制。
- 单条审计详情必须校验 audit id，只允许读取状态目录中的直接 JSON 文件。
- 无法解析或结构非法的审计文件不进入正常列表。

## 验收标准

- 超过一页的操作记录可以前后翻页，且不重复、不遗漏。
- 列表响应不包含 target 明细，详情响应包含完整 target。
- 不合法 operation id 或 audit id 被拒绝。
- 清理与孤立备份维护生成的审计都可以从同一入口查询。
