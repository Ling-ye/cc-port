# 本机状态保留与清理规格

## 目标

控制操作记录和备份的磁盘占用，同时保留足够的恢复点和审计信息。

## 默认策略

- 最近操作保留数量：20。
- 操作保留期：90 天。
- 备份软上限：2048 MiB；设为 `0` 表示不按容量选取候选。
- 清理只处理已结束操作；`running` 操作永不进入候选。
- 所有参数可以在配置文件 `[state]` 中调整，也可以在清理预览时临时覆盖。

## 计划语义

- 清理必须先生成只读计划，展示操作总数、备份总量、候选操作、可回收空间和候选原因。
- 超过保留期且不属于最近保留数量的操作进入候选。
- 超过容量软上限时，从最旧的非保护操作开始追加候选，直到预计容量回到上限以内。
- 没有合法操作记录的孤立备份只统计，不自动删除。
- 生成计划不会修改操作记录、备份或目标资源。

## 执行语义

- 用户显式确认后才能执行清理。
- 执行时重新计算候选；请求中的操作 ID 必须仍属于最新计划，防止删除新近状态。
- 清理使用状态维护锁，不能与涉及相同 operation record 或 backup 的维护操作并发。
- 每次清理写入独立的维护审计记录，记录策略、删除 ID、回收字节数和失败项。
- 清理不删除 `sync/` 工作树；Git 临时工作树仍使用独立的显式清理流程。

## 验收标准

- dry-run 不修改本机状态。
- 最近保留数量和运行中操作不会被选中。
- 容量超限时按从旧到新的顺序追加候选。
- 并发清理不能删除计划生成后变为受保护的操作。
- 单个删除失败不会伪报为已回收，结果中必须列出失败项。
