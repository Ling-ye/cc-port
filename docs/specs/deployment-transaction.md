# 部署事务与所有权规格

## 目标

所有本地 AI 工具写操作均可预览、可验证、可追踪，并在失败时恢复到操作前状态。

事务覆盖两类入口：

- 环境部署：一次部署计划作为一个事务。
- 普通资源安装与卸载：单个资源作为一个事务；批量同步由多个独立资源事务组成。

## ChangeSet

每次部署先生成 ChangeSet，包含：

- 操作 ID、资源、平台和目标路径。
- `create`、`update`、`remove`、`json-patch` 或 `conflict` 动作。
- 写入前后的内容哈希。
- 所有权状态和冲突原因。
- 备份路径与部署后验证方式。

## 所有权

- LPM 创建或更新的目录写入 `.lpm-managed.json`。
- 未带有效管理标记的同名目录不得被静默覆盖或卸载。
- MCP 只管理指定 server entry，不拥有整个配置文件。
- 被移出平台白名单的遗留安装仍允许显式卸载。

## 备份与状态

- 备份和操作记录位于本机状态目录，不得放入资源 Git 仓库。
- Windows 默认路径为 `%LOCALAPPDATA%\LPM\backups\<operation-id>`。
- 其他系统使用用户状态目录；测试可通过 `LPM_STATE_HOME` 覆盖。
- 应用顺序为：计划、备份、写入、验证、记录成功。
- 任一目标失败时回滚本次已写入目标，并记录失败与回滚结果。
- 普通资源事务必须同时覆盖资源缓存、外部仓库 clone、平台目标和 MCP 所有权状态。
- 操作记录中的 `changed_target_count` 表示实际内容发生变化的目标数量；重复安装相同内容时该值为 `0`。

## 验收标准

- 部署不会使资源仓库因备份文件变脏。
- 未管理目录不会被覆盖或卸载。
- 连续部署相同内容时第二次 ChangeSet 为空。
- 中途失败后所有已修改目标恢复。
- 单个资源安装或卸载失败后，缓存、平台目标、MCP 配置和所有权状态全部恢复。
