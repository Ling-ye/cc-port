# 异步任务反馈规格

## 目标

在不改变现有页面布局、导航、业务 API 和视觉体系的前提下，为用户主动触发的长耗时操作与写操作提供统一反馈：

- 操作完成或失败时显示 Toast。
- 顶栏任务入口展示运行数量。
- 右侧非模态任务面板保留当前应用会话的任务历史。
- 页面切换不丢失任务状态。
- 本地扫描提交范围后关闭弹窗并转入会话级后台任务；远端刷新与本地扫描可同时出现在运行列表中。

不引入 Fluent UI、Storybook、任务持久化、取消能力或全局串行队列。

## 状态模型

任务状态仅包含 `running`、`succeeded`、`failed`。每条任务记录包含：

- 会话内唯一 ID、类型、标题和可选上下文。
- 开始时间、可选结束时间和结果消息。
- 重试策略：`safe-read` 或 `none`。
- 执行函数只保存在内存中，不写入磁盘。

任务历史按最新优先展示。最多保留 50 条已完成任务；运行中的任务不得因上限被移除。清理操作只删除已完成任务。

安全读取任务重试时复用原任务记录，并重新进入 `running`；清单类安全读取若已有同来源任务运行，重试必须加入该任务的 Promise，不得绕过来源级 single-flight，也不得提前解除来源 busy。写操作失败后不提供重试按钮，用户必须回到原功能重新确认。

## 反馈行为

- 任务开始时不弹 Toast，继续沿用原按钮的忙碌与禁用状态。
- 成功 Toast 自动显示 4 秒，使用 `role="status"` 和礼貌播报。
- 失败 Toast 自动显示 8 秒，使用 `role="alert"`。
- 最多同时展示 3 条 Toast，均可手动关闭。
- 右侧任务面板为非模态界面，不阻止页面操作；顶栏按钮、关闭按钮和 `Escape` 均可关闭面板。
- 任务标题和消息在任务创建时按当时语言生成，之后切换语言不改写历史记录。

异步任务的成功与失败不再重复写入页面顶部横幅。顶部横幅仅用于应用初始加载失败、同步读取失败和表单校验等需要持续展示的错误。

## 跟踪矩阵

| 操作 | 是否进入任务中心 | 重试策略 |
| --- | --- | --- |
| 手动刷新、资源扫描、批量差异计划、设置页诊断、配置检查 | 是 | `safe-read` |
| 收集、上传、导入、安装、卸载、删除、批量应用、配置保存 | 是 | `none` |
| 初始加载、资源变更后的自动刷新、分支候选加载 | 否 | 不适用 |
| 内容预览、打开目录 | 否 | 不适用 |

多目标写操作中，只要任一目标失败，整条任务标记为失败。下载按“资源 × 工具”独立提交本地事务，已成功目标不自动回滚；上传的远端有效项合并为一次提交。任务中心不得提供一键重试，关闭应用后不保存批次进度。

## 验收标准

- 用户可从顶栏查看运行数量，打开任务面板并清除已完成任务。
- 页面切换后，运行中任务仍会更新为成功或失败。
- 同一异步结果不会同时显示横幅与 Toast。
- 安全读取失败可原位重试；写操作失败没有重试入口。
- 清单任务重试与同来源新任务重叠时只产生一次底层读取和一次清单发布；远端与本地两个不同来源仍可并行，不引入全局串行队列。
- 任务记录遵守 50 条完成历史上限，运行中任务不会被淘汰。
- Toast 的显示时长、并发上限、关闭行为与无障碍角色符合本规格。
