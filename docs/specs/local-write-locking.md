# 本地目标跨进程写锁规格

## 目标

桌面端、CLI 或多个 LPM 进程不能同时修改同一个本地目标，避免快照、写入和回滚互相覆盖。

## 锁粒度

- 锁键使用规范化绝对目标路径，不使用资源名称。
- 一个事务涉及多个目标时，按规范化路径固定顺序获取全部锁。
- 不相交的目标允许并发执行。
- MCP 配置文件和 MCP 所有权文件都属于事务目标，因此会分别加锁。
- 锁文件位于本机状态目录 `locks/`，不得进入资源 Git 仓库。

## 生命周期

- 获取全部锁后才允许创建快照。
- 锁覆盖快照、写入、验证、操作记录落盘和失败回滚全过程。
- 成功、回滚或初始化失败后必须释放已获取锁。
- 操作系统负责在进程异常退出时释放文件锁；持久锁文件只是锁载体，可以保留。
- 默认等待 10 秒；超时后不写入目标并返回冲突目标。

## 验收标准

- 两个进程竞争同一目标时只有一个可以进入快照阶段。
- 两个进程修改不相交目标时可以分别获取锁。
- 多目标事务以固定顺序加锁，不因调用顺序不同产生死锁。
- 进程释放或退出后，另一个进程可以获取相同目标锁。
