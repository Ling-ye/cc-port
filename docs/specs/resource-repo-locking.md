# 资源仓库写锁规格

## 目标

CLI、桌面端和其他 LPM 进程不能同时修改同一个资源 Git 仓库或它的同步计划。

## 锁粒度

- 锁键使用资源仓库规范化绝对路径。
- clone/connect、plan、resolve、apply、cancel、cleanup、commit 和 push 都必须持有仓库锁。
- 只读且不 fetch 的状态检查可以不加写锁；带 fetch 的状态检查必须加锁。
- 一个操作涉及仓库和计划目录时，使用同一个仓库锁覆盖完整调用。

## 生命周期

- 每个 API/CLI 调用独立获取和释放锁。
- 不在等待用户选择冲突期间长期持锁。
- 同一仓库最多存在一个 `conflict` 或 `ready` 活动计划。
- 创建新计划前发现活动计划时返回其 operation id，要求应用、取消或清理。
- 锁超时返回资源仓库正在被另一个 LPM 操作占用。

## 验收标准

- 两个进程竞争同一仓库时，只有一个进入 Git 修改阶段。
- 不同资源仓库可以并行。
- 异常退出后操作系统释放锁，其他进程可以继续。
- 活动合并 worktree 未处理前不能创建第二个合并计划。
